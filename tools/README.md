# Tools

Standalone Python scripts (standard library only); run them with `python -I` from the repository
root.

| Script | What it does |
|---|---|
| `bar.py` | Lists or extracts the files of the game's `.bar` archives, to get stock models, textures and anim XML as references on your own machine. `python -I tools/bar.py <archive.bar> [filter] [--extract <folder>]` |
| `xmbedit.py` | Reads and writes the game's compiled XML (`.xmb`): `check`, `to-xml`, `from-xml` (with `--compress`), and `add-unittype` to add a unit type to protos. `to-xml` keeps each element on its stored source line, so `to-xml` then `from-xml` gives the file back byte for byte (all 14 stock impact effects, protos and tech tree). An impact effect in one command each way: `python -I tools/xmbedit.py from-xml cannon.impacteffect` writes `cannon.impacteffect.xmb` (plain, as the stock ones), `python -I tools/xmbedit.py to-xml cannon.impacteffect.xmb` writes `cannon.impacteffect`; see "Impact effects" in `docs/game-formats.md`. Run it without arguments for the full usage. |
| `ui_preview.py` | Draws a UI layout file (`ui*.xml`, or its `.xmb`) as a PNG: each gadget's `size1024` box coloured by nesting depth and numbered, a legend with names, types and (`--text`) their text, gadgets outside their parent's box in red (`OUT`: they show and hide with that parent), `hidden` ones dashed. `--mark REGEX` highlights new gadgets, `--hide REGEX` leaves some out, `--region x1,y1,x2,y2` picks the part of the 1024 x 768 space. Lenient like the game's parser (comments, upper-case attributes, a stray closing tag). `venv\Scripts\python -I tools/ui_preview.py <layout> --out <png> [--scale 2] [--mark R] [--hide R] [--text] [--title T] [--vline X,X]` (`--vline` draws dashed vertical guides, e.g. a layout's centre line). Needs numpy. Test: `tests/test_ui_preview.py`. |
| `art_survey.py` | Surveys the art of the game or a mod (models, textures, anim files, `.bar` archives in memory) and writes `report.json` and `summary.md`; with `--proto`, joins the buildings to their models and measures them, and `--profile-out` writes the calibration profile. See the main README. The reports name the scanned files: keep them out of public repositories (the profile does not). |
| `build_zip.py` | Builds the installable add-on zips into `dist/`. |
| `build_app.py` | Builds AoE3 Mod Studio as a program (PyInstaller) into `dist/AoE3ModStudio/`; `--zip` also zips it. Run it with a Python that has `pyinstaller` and `numpy`, not the venv with `bpy`. |
| `game_deploy.py` | Puts a game bundle (`scripts/game_export.py` or the add-on's Game Export) into a test copy of the game, runs the mod's validators, or undoes it: `python -I -X utf8 tools/game_deploy.py --install <copy> --bundle <folder> [--validate]`, `--grouping <file.xml>` (into every `RM*/groupings`), `--undo`. Refuses any Steam folder. |
| `fetch_materials.py` | Downloads the material swatches (CC0 photos), checks each source's licence page states CC0 before writing anything, removes their baked lighting, resizes them and writes them with `MATERIALS.md` into `aoe3_blender_tools/materials/`. Needs numpy (the venv). `venv\Scripts\python -I tools/fetch_materials.py [name ...] [--cache <folder>]` |
| `make_texture.py` | Makes a seamless, tileable texture from a picture or from a description, and keeps it in the texture library with its licence and what it was made from (the Texture Maker panel, from the command line). `--no-ai` needs no ComfyUI and no GPU; `--list` prints the library. Needs numpy. See [docs/texture-maker.md](../docs/texture-maker.md) |
| `texture_survey.py` | Opens every texture of a game copy or a mod and measures it (palette, grain, the join, alpha, painted light), tells the mod's own from the original game's with `--reference`, and writes the texture profile (`--profile-out`, measurements only) and contact sheets (`--sheets`, outside any repository). Needs numpy. |
| `model_survey.py` | The same for every Granny file: triangles, bones, vertex layouts, sizes, texture pixels per unit, and how animations are written. Compressed files go through an external bridge into a cache (`--granny`, `--cache`). Writes the model profile. |
| `model_sheets.py` | Renders contact sheets of models with their textures, through the importer: sampled from a model survey, or an explicit list to compare side by side (`--models <list.txt> --game <game folder> --out <sheet.png> [--cell 220] [--cols 6] [--title "..."] [--keep-scale]`), one `caption \| target` per line, the target a proto name, an anim file or a model path relative to `art\`. Each cell has its caption, and a `.txt` beside the sheet says what each one shows or why it is empty; `--keep-scale` puts every model at one scale on one ground line; `--prefer a,b` (or `target@a,b`) picks the branches of the anim files' logics to show (a culture, a civ, an age); the anim file's `<replacetexture>` is applied, and a missing model falls through to the next candidate. `--attachments` also draws what hangs on the model standing (hats, ponchos, weapons, through their own `<replacetexture>`, each laid on its bone at rest); `--views -35,150` renders each entry from several sides; `--team 2850dc` shows a player colour where the textures let it through; `--overlay <folder>` (laid out like a game copy) puts new art and anim copies over the game's before they are installed. Compressed models come from the model survey's cache (`--cache`) or the external bridge (`--granny`). Needs Blender (bpy). Sheets of a mod's art stay outside any repository. |
| `uv_atlas.py` | The UV layout of a unit's model drawn over its texture, each island numbered and coloured by the body part that moves it (from the skin weights of the model, or from where the island sits when it has none), with one mask per part (head, torso, arms, hands, legs, feet, left and right) and `atlas.json` (each island's part, bone and UV triangles) for `retexture.py`. Targets as in `named_models.py`; `--size WxH` draws the masks for an upscaled texture. Compressed models through the survey cache and the Granny bridge (`--cache`, `--granny`). `venv\Scripts\python -I tools/uv_atlas.py <proto, anim or model> --game <copy> --out <folder> [--prefer a,b] [--texture <file>] [--size WxH] [--by bone\|position] [--overlay <folder>]`. Needs numpy. Its pictures show the game's or a mod's art: keep them outside the repository. |
| `retexture.py` | Repaints a texture part by part from a JSON recipe over a `uv_atlas.py` atlas: recolour (keeping the light and folds), tone, fill from a swatch (e.g. `make_texture.py`'s), paste a design in UV space, blur, cloth grain, the player colour's mask, and an optional AI pass per selection (`core/meshtex.py` and `core/airepaint.py`: SDXL held by ControlNet, with the edge guard; needs ComfyUI). Selections combine parts, islands, bones, boxes, masks, colours, bands (`rows`, `cols`) and rims (`edge`). Upscales (a 64 px texture painted at 256 px), writes the `.ddt` as BGRA, DXT1, DXT3 or DXT5 with or without mips, in the start's alpha mode, and a bump map from the result. `venv\Scripts\python -I tools/retexture.py <recipe.json> [--preview <png>] [--url <ComfyUI>]`; the recipe format is in its docstring. `--own-texture <in.gr2> <out.gr2> OLD=NEW ...` writes a copy of an uncompressed model whose stored texture paths read NEW (same length, CRC recomputed): a unit copy that shows its texture without a `<replacetexture>`, for when the game keeps the original's texture on a shared model. Test: `tests/test_retexture.py`. Recipes and textures of a mod stay outside the repository. |
| `recolor_textures.py` | Recolours `.ddt` textures in OKLCH (hue shift, saturation and lightness factors, optionally only a window of hues) and measures them against colours: the mean colour, CIEDE2000 to each player colour (`--player-colors <playercolors.xml or .xmb>`, or `--against NAME=R,G,B`), the share of pixels near each one, the weighted mean of a terrain mix (`--mix`) and a new minimap colour (`--mapcolor`). Each texture keeps its header, format, alpha and every mip level (each recoloured from the original's own); bump maps are skipped. `venv\Scripts\python -I tools/recolor_textures.py <file or folder> ... --out <folder> [--hue DEG] [--chroma F] [--lightness F] [--hue-window C,H[,F]] [--report <json>] [--preview <png>] [--dry-run]`; without a transform it only measures. Refuses a Steam folder and its own input folder as output. Needs numpy. Test: `tests/test_recolor_textures.py`. |
| `named_models.py` | What `model_sheets.py --models` renders: reads such a list and prints what each entry resolves to (a proto through `protoy.xml` and its anim file to the model it shows standing), loose files first, then the `.bar` archives, plain or `.xmb`. `python -I tools/named_models.py <list.txt> --game <game folder> [--overlay <folder>]`; it also lists what hangs on each model (`animxml.idle_attachments`). Standard library only. |
| `style_check.py` | Paints the presets and says how far each texture is from the mod's own building textures; `--fit` measures each material role apart and prints the fine grain band that brings it to the mod's median (`core/materials.py`). |
| `lora_dataset.py`, `train_lora.py` | Pieces of the mod's own textures with captions, and the training of a LoRA on them with the local ComfyUI's own nodes, in resumable chunks and with a watchdog on the PC's free memory. Dataset and LoRA stay outside the repository. |
| `grouping_survey.py` | Reads every grouping (`RM*/groupings/*.xml`) of a game copy or a mod, classes each placed unit by its proto's unit types, measures how settlements are laid out round their socket, and writes `profiles/groupings.json` (numbers only). Standard library only. |
| `gallery.py` | A labelled grid of presets rendered as `scripts/generate.py` renders them: the README galleries (`--style AFRICAN`, `--style PROP --cols 4`). Needs Blender (bpy). |
| `palette_survey.py` | Measures the mean colour and local contrast of the stock building textures in `.bar` archives (the target the swatches' grain is fitted to); prints, writes nothing. Needs numpy. |
| `shape_survey.py` | Studies how buildings are built: mass, levels, parts, where the triangles go, in numbers per class that the generators are held to. |
| `spec_sheets.py` | Writes the technical sheet of every preset into `docs/specs/`: sizes, triangles, texture, collision, shape against the real models. `--proto` adds the game's data (only with `--out` outside the repository). |
| `make_rings.py` | Draws coloured rings that lie on the ground under a unit or building (7 colours, sized by `<logic type="UnitType">`: unit, cavalry, small, medium and large building), markers with a floating resource icon (`aura_<name>.xml`), rank marks (`rank_1` to `rank_5`: chevrons, then stars) and range rings (`range_<metres>`, 4 to 30 m): anim XML, `.particle` files and DXT3 `.ddt` textures, 181 files, nothing taken from the game. A unit shows one with `<modelattachment>effects\<folder>\ring_<name>.xml</modelattachment>`. `python -I tools/make_rings.py [--out <folder>] [--folder <name>] [--check]`: `--folder` is the folder under `art\effects\` the files name (default `rings`); `--check` compares a folder with what it would write. About 40 s (plain Python). |
| `make_icons.py` | Draws three 64x64 DXT1 test avatar icons (a blue diamond, a red cross, a green ring) and the avatar table that names them, for `data\` and `art\ui\playericons\`. `python -I tools/make_icons.py [--out <folder>] [--prefix <p>] [--table <name.xml>] [--check] [--install <test copy>]` (default prefix `test_`; `--install` refuses a Steam folder and keeps a replaced file as `.orig`). |
| `game_fonts.py` | A game copy's interface fonts as a whole. `survey`: every typeface `FONTS\fonts3.xml` names, how many entries use it, where its file is (loose in `FONTS\`, in an archive there, or a Windows font) and which letters of `extend_font.py`'s scope it lacks (read from its character map; standard library). `stage`: each font with a file that lacks letters, extended by `extend_font.py` under `<typeface> <Word>`, written as `<out>\copy\FONTS\<file>_<Word>.ttf` with the copy's `fonts3.xml` pointed at them (`aoe3game/uifonts.retarget`: only those `TypeFace` values change), proof sheets and reports beside; nothing is written in the copy, and `tools/game_deploy.py --files <out>\copy` deploys it (undo takes it out). `python -I tools/game_fonts.py survey --game <copy>`, `stage --game <copy> --out <folder> --suffix <Word> [--families "A,B"] [--only <letters>]`. Test: `tests/test_game_fonts.py`. |
| `extend_font.py` | Adds the accented Latin letters a TrueType font lacks (all of Latin Extended-A, the Romanian comma letters U+0218 to U+021B, Latin-1), each a composite of the font's own base letter and accent, placed as the font's own accented letters are; accents it lacks are made from its shapes (comma below from its comma, the apostrophe caron of ď ť ľ Ľ from its quote, ...). Renames the family, updates cmap, hmtx, OS/2, kern, hdmx and LTSH, keeps every existing glyph and its hinting, and reports what it could not build. Optional dependency: `venv\Scripts\pip install -r requirements-fonts.txt`. `venv\Scripts\python -I tools/extend_font.py <in.ttf> <out.ttf> [--family NAME] [--proof <png>] [--report <json>] [--only <letters>]`. Test: `tests/test_extend_font.py` (a font built in the test). Never commit a font file of a game or a mod. |
| `make_bar.py` | Draws a health-bar texture in any colour, in the layout and shading of the game's own green, yellow and red bars (16x8, DXT1). `python -I tools/make_bar.py [--colour RRGGBB] [--out <file.ddt>] [--check]` (default an orange, `FF8C00`). |
| `make_stat_icon.py` | Draws small stat icons for the unit panels (the pictures a row puts after a value). `--style bold`, the one to ship: 32x32 uncompressed BGRA with one level, as a mod's own stat icons are made, solid shapes with hard edges (alpha 0 or 255), a black contour per part and a 2-texel black outline: a stopwatch (rate of fire), an hourglass (train time), an eye (line of sight), a winged boot (speed), a shield (armor) and a revolver's cylinder (projectiles per reload); round parts are drawn wider than tall, since the panel draws icons narrower than tall. `--style soft`, the first set: 16x16 DXT3, supersampled soft edges (also a heart, a house and two speed variants). Drawn analytically; no pixel comes from a game. `venv\Scripts\python -I tools/make_stat_icon.py [--style bold] [--glyph G] [--out <file.ddt>]`, or `--all <folder>` for every glyph of the style under its file name (`stat_icon_rof.ddt`, ...); `--png` writes an enlarged preview, `--check` compares with the files on disk. Needs numpy. Test: `tests/test_stat_icons.py`. |
| `make_flag.py` | Writes a whole civ flag set from one design image (PNG of the flat flag, hoist on the left): the in-game flag (128x128 BGRA, with procedural folds), the small and large button sets in their four states (normal, click, high, disable) and the postgame flag, in the formats a game copy's own sets use. The postgame flag lies on the painting's cloth by a warp measured on the stock sets (`--fit-warp` refits it on another copy), in a tone and folds fitted on the copy's own pairs, under the stock pole. The frames, the postgame painting round the pole and the colour change of each button state are measured at run time from the copy's sets (the pixels every set shares, a linear fit per state); nothing of the game is stored. `venv\Scripts\python -I tools/make_flag.py --design <flag.png> --name <set> --game <copy> --out <folder> [--flags-dir ...] [--buttons-dir ...] [--preview <sheet.png> --compare a,b] [--fit-warp]`; refuses to write into the copy. Test: `tests/test_make_flag.py`. |
| `gr2_tree.py` | Reads an uncompressed Granny model: the data tree, `--stats`, `--types` or `--shape`. |
| `uncompress_models.py` | Writes uncompressed copies of the archived Granny models of a game copy as loose files under its `art\`, so the game no longer decompresses a model on its main thread the first time it meets one (a stutter mid-match, and part of a save's load). It skips every name that already exists loose (a mod's own models are never touched), models already uncompressed, and names stored differently in two archives; each copy is written by the external Granny bridge (`--granny`, the tool of `art_survey.py`), gets its root type reference back if it lost it, and is checked against its original before it is written. A manifest at the root of the copy (`uncompressed-models.jsonl`) lists every file and folder it created: `--undo` removes exactly those, `--check` verifies them, and a second `--install` follows a patched archive. `--only-used <list>` keeps only the models a list or a game log names. Refuses any Steam folder. `python -I tools/uncompress_models.py <copy> [--install --granny <bridge.exe>] [--check] [--undo] [--only-used <list>]`; with no mode it prints the plan and writes nothing. See "Uncompressed copies" in `docs/game-formats.md`. |
| `gr2_check.py` | The game's own Granny runtime as the judge of a model: what granny2.dll reads (meshes, vertices, indices, bone bindings, skeletons and bones; the helper's `info` verb) beside what `aoe3game/gr2.py` reads, and with `--rewrite` the model written again from its own tree (`aoe3game/gr2_edit.rewrite`), which must read the same in the runtime with a valid CRC. Writes nothing. `python -I tools/gr2_check.py <model.gr2 or folder> --granny-install <game> [--helper <exe>] [--rewrite] [--limit N] [-v]`. Test: `tests/test_gr2_edit.py`. |
| `recompress_models.py` | Compresses Granny models again (Oodle1) through the game's own runtime: the reverse of `uncompress_models.py`, for models a tool wrote uncompressed (`fix_bone_scale.py`, `retexture.py --own-texture`) that should ship at the size of the originals. `--like <original>` keeps each section in the format the original stores it in; without it every section becomes `--format` (default `oodle1`) unless its compressed bytes would not be fewer. It puts back the root type reference the runtime writes as 0:0, recomputes the CRC, and checks every result: same header, section records and fixups, the CRC valid by the bytes and by the runtime, and the runtime expands it back to exactly what it expands the input to. granny2.dll is 32-bit, so a small x86 program hosts it, `granny_recompress.c` (`--build-helper` compiles it with Visual Studio's x86 compiler or zig into `tools/granny_recompress.exe`, ignored by git); the DLL is read from `--granny-install` and never shipped. A file or a folder: `python -I tools/recompress_models.py <in.gr2 or folder> -o <out> --granny-install <game copy> [--like <original or folder>] [-v]`. Test: `tests/test_recompress_models.py`. See "Recompressed copies" in `docs/game-formats.md`. |
| `fix_bone_scale.py` | Brings the attach and impact bones of Granny models to unit scale when an export left them scaled (a root scaled by 100 for centimetres makes the game draw the `.xml` impact visuals hung on them 100 times too big). It changes only bones no mesh is bound to, whose world scale is at least `--factor` (10) off, keeping their place and direction; it patches in place (same size, CRC recomputed), checks the result, and refuses what it cannot handle. A file or a folder: `python -I tools/fix_bone_scale.py <in.gr2 or folder> [-o <out>] [--bones REGEX] [--dry-run] [-v]`; without `-o` it writes in place after a `.bak` copy. Compressed files need `--granny <bridge.exe> --granny-install <game copy>` (the external bridge of `art_survey.py`), and are then written uncompressed. See "Bone scale" in `docs/game-formats.md`. |
| `add_normal_maps.py` | Gives a normal map to every material whose shader reads one (`bumpspec...`) and has none (`aoe3game/gr2_material.py`): the colour texture's own `_b`, `_bump`, `_normal` or `_n` when the art holds one, else one made once per colour texture from its brightness (`ddt.normal_from_texture`, DXT5, usage 6) and written beside it (beside the model for a stock texture). The material gets a "Bump" map naming it. Writes the rewritten models (uncompressed) and the new maps; `normals.txt` lists each. The game's runtime reads the rewritten models as this repository's reader does (77 of 77). |
| `art_lint.py` | Checks a package of new art (a folder holding `art\` with only the new files) against an art lead's rules and counts every breach: `<replacetexture>` left outside comments, paths an anim file names or textures a model stores that are found nowhere (with `--source`, those the source mod lacks too are counted apart as inherited), banned files (.tga .png .jpg .max .psd .precomp .bak, any .xmb), paths outside the layout of a lint file, duplicates, files at a path the game already serves, texture headers and sizes against `reencode_textures.py`'s rules, models not in the converted basis, static attachments left on buildings (`merge_attachments.py`'s test). Exit status 1 while a count is not zero. |
| `bake_textures.py` | Bakes the `<replacetexture>` blocks of anim files into copies of the models they swap textures on: each copy stores the new texture names itself (`gr2_edit.rename_textures`, any length), the anim file names the copy and its blocks are deleted line by line. One copy per source model and set of swaps for the whole run (the same swap in two anim files gives one file), named after its new colour texture and its source (`post_jesuit_house_05.gr2`). A swap whose `<from>` the model does not store, or whose `<to>` exists nowhere, is removed and listed in `bake.txt` (in game such a swap changes nothing). Input: a manifest (anim file, tab, folder for its copies) and the art folders to look in, in order (loose, then their `.bar`). Writes the edited anim files, the copies (uncompressed; `recompress_models.py` compresses them), `clones.tsv` and `bake.txt`. Seen in game, uncompressed and compressed again (`docs/game-formats.md`). |
| `merge_attachments.py` | Merges the static models a building hangs on itself (trees on a plantation, a canopy, a hut) into the building's own models and takes their `<attach>` lines out of the anim file, so the game draws one model instead of the building and every attachment (`aoe3game/gr2_merge.py`: each part placed as the game hangs it, bound to the bone it hung on, rebuilt in the body's types). Every model a component draws (normal, damaged, low detail, death) is merged with the static attachments it hangs; a Variation is fixed to its first pick; an `<include>` whose components draw one static model counts, so nested carriers merge over several passes. Flags, particles, campfires, animated parts, construction stages and character rigs stay attachments, listed in `merge.txt`. Writes the merged models (uncompressed) and the edited anim files. |
| `convert_basis.py` | Puts rigid accessories exported raw from 3ds Max (hats, weapons, cannon barrels, ship rigging: one bone, every mesh bound to it whole) into the form of a converted model: the stock basis (`ESPostExport`, 0.615157485 units per metre, Y up), the object at the origin, one bone with no scale and no animation of its own (`aoe3game/gr2_basis.py`). A raw export keeps the scene it was cut from: the object metres from the origin, the node's scale on its bone (16.6, 64, even 147,732), a track holding that placement. Each vertex goes into the bone's rest frame without the bone's scale, as the game hangs an accessory, so the part stays where it stood on the unit (checked in game, `docs/game-formats.md`, "Attachments at rest"). Only files whose art tool is not `ESPostExport` or whose units are not the stock ones are rewritten (`--all` for every one); `--frombone` names the anim file's attach bone. A skinned body or a part of several bones goes, with `--granny`, through the bridge's `rebake --convert` (the game's runtime converts vertices, bones, inverses and animation curves) and is then named `ESPostExport` (seen in game: 23-bone bodies fought and died as the originals). A mesh-less bone that carries a scale (a mod sizes a creature with it) is refused, as are packed streams. Compressed input through the bridge (`--granny`); compress the results with `recompress_models.py`. Needs numpy. |
| `hc_survey.py` | Inventories the home-city models of a game copy or a mod and plans moving one home city's into a folder of its own; writes nothing into the copy. It reads every `homecity*.xml` (data and campaigns; a top-level visual is relative to `art\homecity\`, a prop's to `art\`), follows their anim files and includes (a loose `.xml.xmb` twin wins), and for each Granny file the mod adds records the home cities that reach it, the anim lines that name it, whether anim files outside the home cities use it too, its basis (art tool, units per metre, up axis), its root and largest bone scale, its size, and each stored texture name with what it resolves to, that `.ddt`'s header digits (the `(u,a,f,m)` suffix of a source `.tga`) and the source images beside it, and each file's and texture's use: `building` (only a building's `<visual>` reaches it), `person` (that anim file holds a Bip01-rigged model: native home cities put people in a building's place), `other` (scene, background, water, path, props), `outside` (a model used outside the home cities too); `textures.csv` gives each texture's use, width, height and bytes. It classes each file: world fix (`basis` for a raw 3ds Max export, `upm1000`, `bone100` for a root scaled by 100, `root_scaled`), texture suffix (`needed` for a `.tga` name without it, `ask` for other names) and move (`yes`, `ask` when shared, `no`). `python -I tools/hc_survey.py --game <copy> --out <folder> --target "<Mod>\homecity" [--cache <survey cache> ...] [--granny <bridge.exe> --work <folder>] [--plan <civ> ...]`; writes `models.csv`, `textures.csv`, `refs.csv`, `summary.md`, `report.json`, and with `--plan` the moves, stored-name renames and XML line changes for that home city.
